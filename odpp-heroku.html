Deploying the ODPP Complaints Console to Heroku

This app isn't Heroku-ready yet — no Procfile, no gunicorn/dj-database-url in requirements.txt, and Whitenoise is installed but not wired into settings.py. Steps below cover what's needed.

1. Add missing dependencies

pip install gunicorn dj-database-url
pip freeze > requirements.txt   # or add the two lines by hand, keep it UTF-8

2. Add a Procfile

release: python manage.py migrate
web: gunicorn core.wsgi

3. Wire Whitenoise + DATABASE_URL into settings.py

MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'whitenoise.middleware.WhiteNoiseMiddleware',   # right after SecurityMiddleware
    ...
]
STORAGES = {"staticfiles": {"BACKEND": "whitenoise.storage.CompressedManifestStaticFilesStorage"}}

import dj_database_url
DATABASES['default'] = dj_database_url.config(default=env('DATABASE_URL'))
The conduct database won't survive on Heroku. It's SQLite on local disk — Heroku's filesystem is ephemeral and wiped on every dyno restart/deploy. Provision a second Postgres add-on (heroku addons:create heroku-postgresql:mini --as CONDUCT) and point DATABASES['conduct'] at env('CONDUCT_DATABASE_URL') the same way. Do this before real conduct data exists.

4. Create the Heroku app and connect GitHub

heroku create odpp-complaints
heroku addons:create heroku-postgresql:mini
heroku config:set DJANGO_SECRET_KEY=... DJANGO_DEBUG=False DJANGO_ALLOWED_HOSTS=odpp-complaints.herokuapp.com

Then in the Heroku dashboard: Deploy tab → Deployment method → GitHub → connect your account → search this repo → connect. Enable Automatic Deploys from main, or use Manual Deploy per push.

5. First release

git push heroku main
heroku run python manage.py migrate
heroku run python manage.py createsuperuser
Django 5.2 needs PostgreSQL 14+ — Heroku's Postgres add-ons default to a current version, so this is fine unless you pin an old plan.

Don't forget

  • DEBUG=False in production — seed commands refuse to run otherwise, which is correct.
  • Set a real DJANGO_SECRET_KEY, not the one in core/.env.
  • MEDIA_ROOT (uploaded documents) is also on ephemeral disk — needs S3 or similar before real documents are uploaded, same issue as the conduct DB.
